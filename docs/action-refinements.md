# 倒地恢复、边线出球与传接球改进（2026-11-18）

基线为 `b744e22`。此前的 4:3、4:3、4:1 属于旧版验收，不能用来证明本次修改的效果。原获胜版本备份为 `D:\boosterRobotics\winning-strategy-three-wins-20261118.zip`。

## 本次修改

| 方向 | 问题与处理 |
| --- | --- |
| 倒地恢复 | `getting_up` 表示异步起身仍在执行，不重复起身、不抢发 walk；状态暂时为空继续等待；再次明确报告可恢复的倒地时允许按冷却重试；确认 normal 后清理旧路径并立即重新参与当前分工。 |
| 起身后动作 | 前 0.8 s 行走限速 0.5 m/s，前 0.25 s 不新启动踢球；同一模式请求间隔至少 0.75 s。该时间仅整形动作，不决定罚下返场或比赛放行。 |
| 边线出球 | 优先传给已在场内、到位且周围有空间的队友；无可靠接应者时选择同侧短斜送，向内约 2 m，避免盲目横穿整个中路；定位球向内分量至少 0.5，避免过浅角度贴线出球。禁区和门线救险仍优先。 |
| 传球锁定 | 未观测到球离脚时锁定传球人，离脚后锁定接球人；准备接应阶段避球，实际来球阶段才进入迎球；接球点随球路预测并对快球下游偏置 0.25 m。 |
| 接球后动作 | 删除慢球近身后立即小力踢向远门的动作。先由位置优势稳定确认控制，再解除接球计划，恢复正常传球或射门选择；路线被堵、来球偏离、越过目标或被对方控制时取消计划，重新争球。 |
| 行走机制 | 新增 `WalkCommand`，限制平移加速度和转向角加速度；限制侧移、后退及移动中转向的组合；距其他机器人 1 m 内限速 0.6 m/s。最终指令仍经过原规则几何检查，暂停、SET 和罚下立即清零，不做缓停。 |

参数集中在 `src/param.py`。保留原前进最高速度、射门力度和攻防比分切换条件。新增限速与提前量均为工程初值，需要物理仿真比较，不能视作已证明的最优值。

## 摔倒风险及证据范围

| 情况 | 为什么可能增加风险 | 本次对应处理 |
| --- | --- | --- |
| 与对手、队友或门柱碰撞，门前多人挤球 | 外力、接触约束和狭窄落脚空间可能破坏平衡 | 保留避障、近身降速、指定唯一接球人；不能保证 SDK 踢球接近过程无碰撞 |
| 大侧移或后退同时大幅转向 | 平移与旋转同时要求较大姿态调整 | 机体速度椭圆包络、移动中转向限制和转向降速 |
| 目标反复切换、突然反向或重新启动 | 指令跳变可能带来较大加速度和角加速度 | 世界坐标速度平滑、传接球角色锁定 |
| 刚起身就全速走或立即踢球 | 姿态可能尚未稳定 | 短暂限速与出脚等待 |
| 起身期间重复起身或切 walk | SDK 异步动作可能冲突；文档明确同组任务可能报错 | 起身状态锁定、重试与模式请求节流 |
| 球在身体侧后方、出脚角度极端，或大力度出脚伴随拥挤接触 | 可能增加支撑和姿态调整需求，具体依赖 SDK 内部动作 | 使用现有对齐与避障；没有因未经验证的推测统一降低射门力度 |

除异步任务冲突外，上表为运动控制与接触机制上的风险解释，未通过本次对照实验量化。不能声称某个速度必摔、力度越大必然越容易摔，或给出未经测量的概率。没有体力因素也仍可能因碰撞、姿态失衡和动作切换摔倒。

既有三场记录只有 R12 出现一次我方倒地未恢复罚下，R13/R14 未见我方处罚；这些样本不足以归因或估计摔倒概率。新增 `RECOVERY` 状态变化日志有助于之后对应倒地前动作、起身状态与恢复耗时。

## 平台限制

- 遵守项目要求，没有修改 `src/framework/`、SDK 步态或官方倒地判定阈值。
- `src/framework/robot_backend.py` 在模式为 walk 时把倒地缓存当作 normal，并跳过 `get_fall_down_state()`。如果真实倒地时模式仍为 walk，策略层可能完全收不到倒地信息。本次无法可靠修复该漏检，也没有另接私有接口或用姿态猜测替代 SDK 状态。
- `get_up()` 返回的是不可取消的异步任务，框架没有保留其 TaskHandle；调用返回不代表已经站稳。策略依据实际收到的状态等待，但缓存行为仍构成限制。
- `kick()` 持续任务内部自行行走，新的行走平滑只覆盖策略下发的 `set_velocity()`，不能宣称覆盖全部底层运动。
- 传球离脚、接球控制和拦截仍是公开位置推算，不是官方触球事实，也不用于解除裁判限制。

## 后续：开球追接与失球回撤

用户反馈：我方斜向开球后等待数秒才追球，容易被断；被断后回撤迟缓，容易形成单刀。这是用户观察，尚未对应逐帧录像归因。代码中确认存在以下问题及修正：

- 开球队友原来执行 `restart:wait`，通过 `wait_away()` 去距离球至少 3.6 m 的等待点。现在指定斜向出球侧的接应人，在约 `(-0.65, 1.9)` 的己方半场、中圈外准备；另一人仍保护后场。
- 官方状态从我方开球切换到 NORMAL 的当帧，立即进入最长 1.5 s 的追接动作：选最快拦截者，用预测点走位并取消旧 SDK 开球接近任务；不再等慢任务追球。首脚斜向轻推和原射门距离闸门保留；不凭本地时间或球位移提前解除官方开球限制。
- 原 `COUNTERPRESS_S=3.0` 虽设置了截止时间，却没有用于动作分配。现在位置估计从我方控制变为对方控制时，只有最近的前场球员反抢，最长 0.8 s，其他人当帧回防。人球距离超过 1.8 m 或球已越过反抢者身后 0.8 m 时提前结束，防止无效追赶。
- 窗口结束后，前场两人按预计来球位置分别回球门侧封堵持球人和保护线路；短暂变成无人控制的球不会重新启动反抢计时。回到球门侧且球真正到脚边时仍可争球，门线救险优先。重新获得近球优势后恢复正常攻防。
- 回防时取消旧踢球、清理旧路径和行走方向。长距离回撤先转向路线、向前走，接近防区才面向球；不再始终看着球低速倒退。出击到前方的最后保护者也使用这一回防动作。

没有新增或回退任何球的仰角、高度、竖直速度、施力模型或物理引擎逻辑。没有实现主动挑射功能。

本轮新增 9 项跨帧回归，总计 **99 项假后端测试通过**，包括官方放行当帧追接、限制未解除时仍不追接、0.8 s 到期、提前放弃、反抢窗口不重开、重新获得球权、SDK 持续踢球取消、门线救险优先和回防朝向。源码编译及差异检查通过。此次后续修改尚未重新部署或启动新比赛，原仿真启动记录属于上一批代码；不能把它作为这批开球/回防修改的物理验证。

## 后续：自由球先手优于被动回撤

用户补充反馈：对手出球进入我方半场、尚未追上时，我方更近却仍挡在球门前等待。代码原因是 `transition_active` 在反抢结束后保持回撤，直到我方进入 1.4 m 的近球优势范围才退出；旧的对方持球估计也可能继续维持 0.8 s。

新增自由球争抢判断，放在回撤分支之前：用现有球路模型分别估计双方到运动球的时间，我方预计早至少 0.15 s、且对手未贴住球（距球大于 1 m）时，立即派最快的可用球员出击。受罚、未起身及未知自身位置者仍由入口过滤；正在绕行受阻者的到球时间会计入原有惩罚。0.15 s 是工程初值，模型没有完整模拟步态和碰撞，不能保证实际一定先到。

远处快球直接迎预测点，不先退到球与门之间；进入可出脚范围后向前场或空边路解围，中路通道被封时允许选择侧向通道。只让一人出击，其余人补球门及身后线路；门将能赢得自由球时允许出击，由另一人接替门线保护。领先至少两球也可主动解围自由球，仍保持余下人员的保护位置。

反抢的 0.8 s 是对方持球时的追抢上限，不是自由球的争抢禁令。若对手又贴近球或我方不再有到球优势，立即回到原短反抢/回撤流程，不重开失球计时。保留正在进行的己方传球与开球追接交接，门线救险仍优先。

新增 7 项回归，累计 **106 项假后端测试通过**；覆盖旧对方持球估计和过期回撤下抢先拦截、立即启动解围、中路封堵后的边路出球、门将出击补门、领先两球仍争球，以及先手丢失后的取消。新增决策没有修改框架或球的物理模型，本批修改尚未重新部署或完成物理仿真验证。

- 角球保持唯一主罚；发现主罚到球的直线路径被队友挡住后，本次角球锁定 robot1。若 robot1 受罚、倒地或暂时换位不能执行，则由一个可用队友接替，避免重新选回不可行动的人。切换后取消原主罚任务。

## 实测后的争球连续性修正

上述版本随后已在 Studio 完整运行一场，tid=2238，最终 2:3。两次角球分别 5 秒、6 秒开出；我方出现一次倒地未恢复处罚。日志确认争球者在约 0.03～0.2 秒间隔内反复换人、取消 SDK 任务，具体事件见 `docs/simulation-issues.md` 的本轮记录。

本次修正让短反抢和球门侧抢断共用处理者迟滞，近似等距时保持当前人选，队友明显更近 0.6 m 才接替；失球估计不再清空处理者。资格仍每帧检查，被突破或不可用的人不能因保持机制继续占位。自由球处理者允许已有 0.45 秒的预计到球时间余量，但仍需比对手早 0.15 秒，否则换成真正能赢得争球的队友；仅实际换人时刷新保持时间。

新增 4 项跨帧/状态回归，累计 **120 项测试通过**，覆盖近似等距抖动不取消踢球、被突破及时交接、失球保留候选，以及自由球预测小变化保持处理者。传球计划和无禁圈投影补了准确类型，静态检查 main/tactics/rules 仅剩宿主缺 SDK 导入提示，未靠关闭检查消除诊断。完整 2:3 比赛是修正前证据，不是修正后的胜率验证。
