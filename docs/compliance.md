## 本次异常修正

- 重开回位：READY 清除旧踢球、进攻路线和卡住记忆，优先返回最近合法区域；允许直接后退、侧移，无须先转身。中圈仍作为禁圈，路线不为了到固定站位而继续深入对方半场。SET / stopped 仍必须停止，不能以“回位”为由移动。
- 卡住改道：约 1.4 s 没有 0.18 m 位移时尝试交替方向的短绕路；目标、连续线段与速度仍经过场界、半场和定位球禁圈检查。
- 官方返场：罚下状态解除或球员重新就绪时，清除旧撤离、绕路和传球计划，当前帧重新分工；进攻时保留已在场的保护者，返场队员可直接补接应位置。
- 门线救险：进球、死球、重开只看官方阶段。球压己方门线且仍为 NORMAL 时，最近可用球员立即解围，其余继续保护。救险时场内踢球工程余量可缩小到 0.03 m，但不绕过停止、罚下、对方重启禁圈或 G-03 闸门。
- 救险不能永久豁免无活动检查：连续尝试约 4 s 无真实位移时取消踢球、在附近约 0.75 m 范围换位，暂由可用队友处理球；完成实际位移后重新分工。普通等待和对方重启仍采用远离球的策略。

## 球路估计

从官方球位差分估计速度，只在远离机器人且方向变化较小时拟合滚动减速度；摆球、暂停、观测中断或明显跳变时重置速度历史。用不超过 2 s 的预测选择拦截点和门前封堵位置，不假设围墙反弹，也不假设球员能够冲刺。

实际比赛日志曾观测到峰值球速 3.22 m/s、减速度估计 0.809 m/s²（255 个被模型接受的滚动样本）。这些是比赛中的在线估计，受观测滤波与碰撞影响，不能当作引擎固定物理参数；踢球力度样本也只是命令与球运动的相关性。

## 剩余风险与信息限制

1. 公开框架没有触球身份、独立 ball_free/expired 字段，因此只用官方提供的阶段/重启状态判定对方限制解除；射门只采用距离条件，不猜测触球人数。首次有效球观测可能晚于摆球；同类重启也依赖广播中可观察的阶段变更才能区分。
2. SDK 持续踢球会自行接近球，无法套用策略的逐步速度限制；每帧重新检查并取消，仍存在采样间隔、机器人惯性、碰撞和定位误差。不能保证绝对零犯规。
3. SDK 文档明确 get_up 任务不可取消；框架也未向策略暴露慢操作任务句柄。停止阶段不新启动，但此前已在执行的起身不能由策略保证立即停止；没有修改框架或编造取消接口。
4. 已在禁区内时采用真实径向撤离；若多个禁圈与场界互相挤压、没有可行撤离速度，安全闸门选择停步，仍可能被裁判判非法位置。后续应结合实际时间线调整余量。
5. 当前无球/无姿态时停止，优先避免盲动。传感缺失过久、SDK 起身失败或物理卡住导致的无活动仍需实际比赛验证。
